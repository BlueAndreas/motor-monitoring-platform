## Modbus 数据约定

地址为 `127.0.0.1:1502`，从站号 1，读取功能码 03。地址使用从 0 开始的协议地址。

| 地址 | 字段 | 类型 | 还原方式 | 单位 |
| --- | --- | --- | --- | --- |
| 0 | winding_temp_c | UInt16 | raw × 0.1 | ℃ |
| 1 | bearing_temp_c | UInt16 | raw × 0.1 | ℃ |
| 2 | current_a | UInt16 | raw × 0.1 | A |
| 3 | speed_rpm | UInt16 | raw | r/min |
| 4 | running | UInt16 | raw | 0/1 |
| 5 | sample_seq | UInt16 | raw | 0～65535，循环计数 |

模拟器正常输出 `running=1`，冻结工况保持数值和序号不变。温度、电流先乘以 10 存为整数，在读取端恢复小数。当前模拟模型不覆盖负温度或真实电机的动态响应。

## 健康检查

`HealthWatcher` 每约 2 秒读取六个寄存器，单次通信超时为 3 秒。它跟踪采样序号的最后变化时间：超过 15 秒无变化时标记 `stale=1`。序号从 65535 回到 0 仍视为更新。

| 字段 | 含义 |
| --- | --- |
| comm_ok | 本轮是否成功取得六个寄存器 |
| stale | 样本是否未建立或超过 15 秒未更新 |
| data_valid | 通信成功、未过期且数值范围合理时为 1 |
| data_age_s | 距离采样序号最后一次变化的秒数；未知时为 -1 |
| last_poll_ok_ts | 最近成功轮询的 UTC 时间戳，单位毫秒 |
| last_sample_change_ts | 最近采样序号变化的 UTC 时间戳，单位毫秒 |
| last_error | 最近一轮通信错误的简要类别 |

合理性范围为温度 0～200 ℃、电流 0～1000 A、转速 0～6000 r/min、运行状态 0/1。这些是原型的数据检查边界，和设备过温、过流告警阈值不同。过温样本可以仍然有效；断线或冻结不能因为保留了旧值就被判断为正常。

## IoTGateway 接入约定

参考上游提交 `8de442a7dec52d2993d1e9667d799846936d681b`，该版本源码目标为 .NET 10，与本仓库 .NET 8 的独立健康检查程序分别构建。

| 配置项 | 取值 |
| --- | --- |
| 设备驱动 | ModBusMaster |
| 主站类型 | Tcp |
| 设备地址 | 127.0.0.1 |
| 端口 | 1502 |
| 从站 | 1 |
| 方法 | HoldingRegisters |
| 变量类型 | Uint16 |
| 变量地址 | 0～5，按寄存器映射文件配置 |
| 温度和电流表达式 | raw * 0.1 |

北向平台选择 ThingsBoard，MQTT 地址为 `127.0.0.1:1883`；网关设备令牌作为用户名。ThingsBoard 中应创建网关设备并启用网关标记，电机数据使用网关遥测 API。实际网关参数、设备创建和上报仍需在对应版本中联调。

平台看板和告警持续时间、确认、恢复配置属于后续集成范围，本仓库不将其列为已完成的功能。
